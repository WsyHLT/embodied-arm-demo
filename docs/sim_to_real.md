# Sim-to-Real 设计说明

本文档解释本 demo 如何处理"仿真 → 真机"的鸿沟，是面试里最能体现工程思维的
部分。核心观点：**仿真帮我们验证"规划决策"，真机的价值在于暴露"执行不完美"，
两者结合才构成完整的具身智能系统。**

## 1. 仿真与真机的差异清单

| 维度 | 仿真(MuJoCo) | 真实 UR 机械臂 |
|------|--------------|----------------|
| 关节到位 | 精确(运动学设 qpos) | 有公差(±0.1°~0.3°), 重力下垂 |
| 控制延迟 | ~0 | 50-200ms(通信+伺服) |
| 动力学 | 无摩擦理想 | 关节摩擦/粘滞/惯性 |
| 物体位置 | 直接读坐标 | 需相机+检测+手眼标定(有噪声) |
| 夹爪 | 无真实夹爪, 用"吸附"模拟 | 电动/真空夹爪, 力反馈判断成功 |
| 轨迹 | 运动学插值 | 需避奇异/避障规划 |

## 2. 本 demo 的分层处理

### 决策层(与真机无关, 可放心复用)
- 指令解析(DeepSeek)
- 物体识别与定位
- pick & place 动作序列

### 抽象层(HAL, 换真机的关键)
- `ArmInterface` 定义统一接口
- `MuJoCoArm` / `RealURArm` 两个实现, 上层代码零感知

### 执行层(仿真简化, 真机需替换)
- 关节控制: 运动学插值 → 真机用 UR 伺服/ MoveIt 轨迹
- 夹爪: 位置吸附 → 真机用真实夹爪 + 力传感器
- 视觉定位: 读仿真坐标 → 真机用 RGB-D + 检测 + 手眼标定

## 3. 量化鲁棒性: test_sim2real.py

给仿真注入真机特性(延迟/噪声/粘滞), 对比抓取放置误差:

```
理想控制      : 0.0000 m   (精确)
真机特性(带噪声): 0.3231 m  (偏差, 暴露鲁棒性问题)
```

**结论解读(重要):**
- 带噪声时放不准, 说明**纯开环 IK 控制对真机不完美敏感**
- 工程上要缩小 gap, 需要:
  1. **视觉伺服**: 放置前用相机二次定位, 闭环纠偏(而非开环一次到位)
  2. **增大吸持容差**: 夹爪/吸盘的容差 > 定位噪声
  3. **力/触觉反馈**: 检测物体是否真的被抓住, 失败则重试
  4. **规划冗余**: 多起点 IK + 轨迹校验, 避免奇异点

这正是真机落地项目里大家在做的事——**不是把仿真做"真"，而是让控制
对不完美鲁棒**。

## 4. 真机部署 checklist

- [ ] `RealURArm` 接入 `ur_rtde`(真实 IP: 端口)
- [ ] 相机标定: 相机 → 机械臂基座坐标系变换(手眼标定)
- [ ] 物体检测: GroundingDINO/YOLO → 2D 框 → 深度 → 3D 抓取点
- [ ] 夹爪: 替换吸附逻辑, 用夹爪反馈确认"抓住/掉落"
- [ ] 轨迹: 引入 MoveIt/UR 脚本端口 `movel`/`movep`, 避免奇异
- [ ] 验证脚本: 同 `test_sim2real.py`, 换成真机实测误差
